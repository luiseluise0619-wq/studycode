# 코드런

AI와 함께 만들면서도 코드의 뜻을 이해하고, 결과를 검사하며 직접 고치는 연습을 해요. 작은 앱의 한 줄부터 시작해 구현·장애 해결·설계와 운영으로 이어 가요. 입문·중급·시니어는 학습 범위이며, 완료 기록이 직무 등급이나 실무 경력을 대신하지는 않아요.

## 시작하기

압축을 풀고 `index.html`을 브라우저로 열어요. `data/`, `vendor/`, `icons/` 폴더를 함께 두세요. 기본 학습과 작은 앱 실습은 설치나 계정 없이 시작해요.

PWA와 오프라인 캐시를 사용하려면 HTTP 서버로 열어요. 저장소 폴더에서 다음 명령을 실행하고 `http://localhost:4173`에 접속해요.

```sh
python -m http.server 4173
```

Python 실행기의 첫 준비, 선택형 AI 도움, 외부 언어 실행 서버처럼 추가 연결이 필요한 기능은 해당 화면에서 안내해요. 받지 않은 학습 자료는 오프라인에서 새로 불러올 수 없어요. 진도·작성한 코드·복습 기록은 현재 브라우저에 저장하며, 백업 파일로 내보내고 복원할 수 있어요.

## 배울 내용

| 학습 공간 | 내용 |
|---|---|
| 분야별 레슨 | 38개 분야 · 936개 단원 · 2,928개 레슨 · 제공하는 문제 13,851개 |
| 작은 앱 | 장바구니·검색·할 일·입력 검사·데이터 요청·메모, 6개 앱의 12개 실습 |
| 다른 상황에 적용 | 6가지 상황의 18개 변형과 독서 목록 앱 3단계 |
| 완성 앱 | 가계부·습관·단어장·예약·게시판, 5개 앱의 25단계 |
| 프로젝트 판단과 운영 | 100개 프로젝트의 765단계 |
| 직접 만드는 프로젝트 | 기존 16개 프로젝트의 84단계와 이어서 만드는 예약 서버 18단계 |

문제 원본은 13,852개이며 알려진 오류 문항 1개를 앱에서 제외해요. 기존 빌드 프로젝트 중 JavaScript 11개·69단계는 앱에서 실행하고 채점해요. 다른 언어 5개 프로젝트는 별도 실행기가 필요해요.

예약 서버 과정은 같은 코드에 기능을 쌓아요. 입문 4단계에서 입력·예약·취소를 만들고, 중급 7단계에서 권한·저장·재시도를 다뤄요. 마지막 7단계에서는 성능·마이그레이션·장애 대응과 검사 설계를 연습해요. 완성한 Node.js 서버 파일을 받아 로컬에서 실행할 수 있어요.

## 공부하는 방식

- 용어의 뜻과 코드의 흐름을 읽고 작은 부분을 직접 고쳐요.
- 실행 결과와 실패한 입력을 확인하고 다시 검사해요.
- 답을 맞힌 뒤에도 해설과 관련 개념을 읽어요. 어울리는 일상 비유를 함께 보여 줘요.
- 최근 정답·힌트·서로 다른 문제·직접 구현 기록으로 분야별 난이도를 조정해요.
- 작성 중인 공부를 이어 주고, 헷갈린 문제와 오래전에 배운 내용을 다시 추천해요.
- 혼자 처음 해결한 답과 해설·힌트를 보고 고친 답을 구분해 기록해요.

AI 도움은 선택 사항이에요. 질문을 만들고 복사하는 기능은 외부 AI에 자동으로 보내지 않아요. AI를 연결하면 제출 전에는 힌트와 개념을, 제출 후에는 답의 근거와 코드 리뷰를 요청할 수 있어요.

## 2026-10-05 문장과 설명 개선

화면 안내·문제·보기·해설·이론·프로젝트 설명의 문체와 표현을 다듬었어요. 설명은 해요체로 맞추고, 메뉴와 짧은 제목은 간결하게 유지해요. 코드 안의 문자열, 실제 출력, 실행 검사와 정답 판정에 쓰는 값은 일반 문장과 구분해 보존해요.

38개 분야에 비유를 추가하고 175개 용어의 뜻·예시·비유의 한계를 정리했어요. 배열의 인덱스와 DB 인덱스, 통계의 회귀와 회귀 테스트처럼 이름이 같은 개념은 맥락을 확인해 설명해요. 보기 80묶음과 추가 보기 89개를 다시 썼으며 일부 항목은 서로 겹쳐요. 출력 읽기 문제 39개는 직접 적도록 바꾸고 대소문자를 구분해 채점해요.

문장을 바꿔도 기존 진도가 이어지도록 문제 ID와 레슨의 저장용 이름을 유지해요. 저장된 오답은 해당 분야를 불러온 뒤 새 설명으로 갱신하며, 기존 복습 간격과 완료 기록을 보존해요. 앱 코드와 오프라인 캐시는 v13이에요.

문체·구조 검사와 대표 내용 검토를 진행했어요. 전체 문제의 사실관계를 사람이 하나씩 재검수했거나 실제 학습자의 습득 속도를 측정한 결과는 아니에요.

수정한 C의 오버플로·패딩 설명은 [C11 위원회 초안의 6.5와 6.2.6.1](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)을 확인했어요. 시각 비교와 스레드 설명은 [Go time 문서](https://pkg.go.dev/time#Time.Equal)와 [Python threading 문서](https://docs.python.org/3/library/threading.html)를 참고했어요.

## 검증과 수정 도구

Node.js로 검사를 실행해요. 브라우저 검사는 Playwright와 Chromium이 필요하며 Windows에서는 기본으로 Edge를 사용해요. 일부 검사는 `PLAYWRIGHT_CHROMIUM`으로 실행 파일을 지정해요.

```sh
node tests/app.test.cjs
node tests/engine.test.cjs
node tests/reader-copy.test.cjs
node tests/vibe-cache-migration.test.cjs
node tests/service-path.test.cjs
node tests/vibe-projects.test.cjs
node tools/content/audit_all.cjs
```

전체 앱 회귀 176개, 엔진 163개, 학습 추천 20개, 학습 품질 30개, 용어 도구 10개, 빌드 실행 16개, 서비스 워커 10개 검사를 통과했어요. 예약 서버의 누적 동작 검사 333회와 화면 검사 42개, 완성 앱 5개의 예시 25개·미완성 초안 25개·동작 검사 151회와 화면·저장·내보내기 검사 64개도 확인했어요. 새 문장 회귀 검사는 진도·오답 갱신, 출력 판정, 비유, 용어의 맥락과 모바일 폭을 검사해요. 캐시 갱신 검사는 준비 완료를 확인한 뒤 오프라인으로 다시 열어요.

문장 수정 도구는 `tools/content/reader-copy.cjs`에 있어요. `--inventory`는 후보 표현을 모으고 `--write`는 보호한 코드·정답 영역을 제외한 문장을 수정해요. 용어와 비유는 `reader-concepts.json`, 분야 소개는 `reader-tracks.json`, 검토한 보기는 `reader-options.json`과 `reader-option-edits.json`에서 관리해요. 원본 작성 스크립트를 다시 실행했으면 문장 수정 도구와 회귀 검사도 실행해요.

추가 검사 설명은 [tests/README.md](tests/README.md), 기존 구조 문서는 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)에서 읽을 수 있어요. [docs/V3_DESIGN.md](docs/V3_DESIGN.md)는 계정·클라우드 저장을 포함한 별도 확장 설계이며 현재 구현과 구분해요.
