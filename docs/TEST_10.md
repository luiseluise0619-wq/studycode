# 10명 테스트 — 재생 뷰어가 실제로 이해를 만드는가

다음 마일스톤은 코드가 아니다. **10명이 써 보고 "이거 때문에 이해됐다" 라는 반응을 얻는 것**이다.
이 문서는 그 테스트를 어떻게 돌리고, 무엇을 통과로 볼지 미리 정해 둔 것이다.

기준을 미리 정하는 이유: 결과를 보고 나서 기준을 만들면 반드시 통과한다.

---

## 무엇을 테스트하나

`홈 → "코드가 도는 걸 눈으로 본다" 카드 → 예제 6개` 중 **하나**.
전부 보여 주지 않는다. 한 사람당 하나면 된다.

| 예제 | 노리는 오해 |
|---|---|
| `basic` | 변수에 값이 언제 담기는가 |
| `range` | `range(1, 5)` 가 왜 4까지인가 |
| `swap` | 먼저 덮어쓰면 원래 값이 사라진다 |
| **`alias`** | `b = a` 는 복사가 아니다 ← **1순위** |
| `scope` | 함수 안 `n` 과 밖 `n` 은 다른 상자다 |
| `error` | IndexError 가 나기 직전의 값 |

`alias` 를 최소 5명에게 준다. 여기서 반응이 안 나오면 나머지도 안 나온다.

Pyodide 없이도 6개 예제는 전부 돈다. "내 코드로 해보기" 는 Pyodide 가 필요하다 —
아직 검증 전이므로 테스트 대상에 넣지 않는다.

---

## 대상

**파이썬을 배우다 만 사람.** 실무 개발자 아니고, 완전 초심자도 아니다.
`b = a` 를 이미 정확히 아는 사람에게 보여 주면 아무것도 측정되지 않는다.

시작 전에 한 줄로 거른다 — "리스트를 다른 변수에 넣어 본 적 있어요?" 있다고 하면 진행.

---

## 진행 (한 사람 5분)

1. **먼저 코드만 보여 준다.** 뷰어 없이, 종이나 화면에 소스만.
   ```python
   a = [1, 2, 3]
   b = a
   b.append(4)
   print('a =', a)
   ```
   묻는다: **"마지막 줄에 뭐가 찍힐까요?"** 답을 적어 둔다.

2. 뷰어를 열고 **아무 설명도 하지 않는다.** 화살표만 알려 준다.
   설명을 해 주면 이해시킨 건 화면이 아니라 나다.

3. 다 넘긴 뒤 묻는다.

---

## 물어볼 것 / 묻지 말 것

**묻는다**
- **"이거 보고 뭐가 이해됐어요?"** ← 핵심 질문
- "3단계에서 무슨 일이 일어난 거예요?"
- "다시 설명해 준다면 어떻게 말할래요?"

**묻지 않는다**
- "좋아요?" · "재밌어요?" · "도움이 될 것 같아요?"
  → 전부 예의상 예 라고 답한다. 측정이 아니라 칭찬 수집이다.

**절대 하지 않는다**
- 힌트 주기, "여기 보세요" 하고 손가락으로 짚기, 막힐 때 설명해 주기.
  막히는 것도 결과다.

---

## 신호 판정

**강한 신호 (통과로 센다)**
- "아 그래서 b도 같이 바뀐 거구나"
- "둘이 같은 걸 가리키고 있는 거네요"
- 1번에서 틀린 답을 적었고, 지금은 **왜 틀렸는지를 말한다**

**약한 신호 (통과로 세지 않는다)**
- "신기하다" · "재밌네요" · "좋은 것 같아요"
- "이해했어요" (무엇을 이해했는지 못 말하면 0)

**실패 신호 (이건 기록이 더 중요하다)**
- 화면을 보고도 1번의 오답을 그대로 유지
- 어디를 봐야 하는지 몰라 헤맴
- 다 넘기고 "그래서 뭐요?"

---

## 통과 기준 (미리 고정)

10명 중 **강한 신호 6명 이상** → 방향이 맞다. 다음은 수집기.

3~5명 → 화면 문제다. 기능을 더 붙이지 말고 이 화면을 고친다.
어느 단계에서 눈이 멈췄는지가 답을 준다.

**2명 이하 → 방향을 다시 본다.** 언어를 늘리거나 예제를 늘려서 될 일이 아니다.
"코드를 되감아 보면 이해된다" 라는 전제 자체가 틀렸을 수 있다.

**말을 요약하지 말고 그대로 옮긴다.** 요약하는 순간 내가 듣고 싶은 말로 바뀐다.
